# PostgreSQL and Prisma database design

This is a Phase 0 logical design. It is not yet a Prisma schema or migration.

## Conventions

- Primary keys use UUIDs generated by the application or database.
- Mutable entities include `createdAt` and `updatedAt` in UTC.
- `deletedAt` is limited to entities where recovery or retention is justified; security records are revoked, not silently deleted.
- Emails are trimmed, Unicode-normalized, and stored with a canonical lowercase lookup value.
- Phone numbers are validated and stored in E.164 format.
- Passwords, OTPs, refresh tokens, recovery codes, and provider secrets are never stored in plaintext.
- State transitions use enums plus service-level transition validation.
- Tenant-owned operational tables carry `organizationId`; branch-owned records also carry `branchId` where applicable.

## Identity and profile entities

### User

- Identity root: `id`, canonical email/phone, password hash, account status, email/phone verification times, last login time, timestamps.
- Unique partial lookups for canonical email and E.164 phone.
- Indexes on status and last login.
- Soft deletion may be used only with anonymization and retention rules.

### UserProfile

- One-to-one user presentation data: display name, preferred language, timezone, avatar reference, accessibility preferences.

### CustomerProfile

- One-to-one customer data: customer number, service tier, default organization context, billing preferences.
- Service tier supports standard and VIP behavior without turning tiers into authorization roles.

### EmployeeProfile

- One-to-one workforce data: employee number, job title, employment status, hire/termination dates, primary branch.
- `jobTitle` is explicitly separate from roles.

### RiderProfile

- One-to-one rider data: availability, vehicle type, vehicle identifier, license metadata, capacity, operational status.

### PartnerProfile

- One-to-one partner-user data: partner reference, partner organization, external reference, partner status.

## Tenancy and authorization entities

### Organization

- Tenant boundary: name, slug, type, legal/display metadata, country, timezone, status.
- Types support delivery company, partner, tuition partner, and future organization categories.
- Unique slug; indexed status/type.

### Branch

- Organization child: code, name, address, timezone, status, parent branch when hierarchy is needed.
- Unique `(organizationId, code)` and indexed `(organizationId, status)`.

### OrganizationMembership

- Connects users to organizations with membership status, default branch, start/end dates, invitation source.
- Unique active membership per `(userId, organizationId)`.
- Indexed user and organization membership lookups.

### Role

- Named permission bundle with scope type (`SYSTEM`, `ORGANIZATION`, `BRANCH`), system-managed flag, organization owner where custom.
- Unique system role key or unique `(organizationId, key)` for custom roles.

### Permission

- Immutable permission key, description, risk level, step-up requirement, scope capabilities.
- Unique permission key.

### UserRole

- Assigns a role to a user within system, organization, and optional branch scope.
- Includes grantor, validity window, revocation metadata, and reason.
- Unique active assignment across user/role/scope.
- Indexed role resolution by user, organization, branch, and validity.

### RolePermission

- Many-to-many role permission mapping with optional constraint metadata.
- Unique `(roleId, permissionId)`.

## Authentication and security entities

### Session

- User login session: device, IP/risk metadata, authentication strength, selected workspace, issued/last-seen/expires/revoked times, revocation reason.
- Indexed active sessions by user and expiry.

### RefreshToken

- Rotating opaque token record: session, token hash, family identifier, sequence, issued/expiry/consumed/revoked times, replacement linkage.
- Unique token hash; indexed active family and session tokens.

### UserDevice

- Registered device: stable server-generated identifier, user agent summary, platform, display name, trust state, first/last seen, revoked time.

### LoginAttempt

- Security telemetry: identity hash, user when resolved, success/failure category, IP prefix/risk data, device, timestamp, request ID.
- Retention-limited and indexed for rate limiting and investigation.

### OtpChallenge

- Purpose, channel, destination hash, code hash, expiry, attempts, resend count, consumed/revoked times, user/session context.
- Indexed active challenges by purpose and destination hash.

### OAuthAccount

- Provider identity link: user, provider, provider subject, normalized provider email metadata, token metadata only when required and encrypted.
- Unique `(provider, providerSubject)`.

### PasskeyCredential

- User WebAuthn credential: credential ID, public key, counter, transports, RP ID, device label, backed-up state, last-used/revoked times.
- Unique credential ID.

### MfaMethod

- User MFA method: type, label, encrypted provider metadata where required, verified/preferred/revoked times.

### RecoveryCode

- MFA method/user linkage, code hash, created/used/revoked times.
- Never stores or returns the original code after enrollment.

### Invitation

- Organization/branch invitation: destination hash and normalized destination, intended roles/job title, inviter, expiry, accepted/revoked state, token hash.
- Unique active token hash and indexed pending invitations.

## Delivery entities

### Package

- Organization-owned shipment: collision-resistant tracking code, sender/customer, recipient snapshot, origin/destination branches/hubs, service level, payment mode, COD amount, quoted/charged totals, weight, lifecycle status, timestamps.
- Unique tracking code globally or by approved namespace.
- Indexes on customer, organization/status, branch/status, tracking code, and creation time.

### PackageAssignment

- Package-to-rider/workforce assignment history: assignee, branch, assignment status, assigned/accepted/completed/cancelled times, assigner, notes.
- Prevents multiple conflicting active assignments through transactional constraints.

### TrackingEvent

- Append-oriented package event: public-safe event type/message, internal details, location/hub, actor, event time, sequence, visibility.
- Indexed `(packageId, eventAt)` and public tracking lookups.

### CustomerRequest

- Pre-package booking request: customer, collection/delivery addresses, package details, quoted fee, approval state, reviewer, decision time/reason, resulting package.

### Hub

- Organization/branch operational hub: code, name, address, coordinates, capacity, status, timezone.
- Unique `(organizationId, code)`.

### PricingRule

- Organization/branch/service-scoped effective-dated rule: base rate, distance/weight bands, urgency markup, currency, priority, effective window, status.
- Indexed active rule resolution by organization, branch, service, and effective time.

### Address

- User/customer/organization address: normalized lines, locality, district, postal code, country, coordinates, label, verification state.
- Sensitive location data follows access and retention controls.

## Operations and governance entities

### Activity

- User-facing operational activity associated with organization, branch, package, request, or actor.
- Separate from immutable security audit logs.

### AuditLog

- Append-only sensitive action record: actor, session, organization/branch, action, resource type/id, outcome, request ID, redacted metadata, timestamp, integrity metadata.
- Indexed by organization/time, actor/time, resource, action, and request ID.

### ApprovalRequest

- Generic approval workflow: organization/branch, type, target resource, requested action, requester, state, required permission, reviewer, decision reason/time, expiry.
- Supports staff approval, rider approval, and future sensitive actions.

## State enums

- Account: `PENDING`, `ACTIVE`, `SUSPENDED`, `DISABLED`, `TERMINATED`.
- Membership: `INVITED`, `PENDING`, `ACTIVE`, `SUSPENDED`, `REVOKED`.
- Invitation: `PENDING`, `ACCEPTED`, `EXPIRED`, `REVOKED`.
- Approval: `PENDING`, `APPROVED`, `REJECTED`, `CANCELLED`, `EXPIRED`.
- Session/token: active state is derived from expiry, consumption, and revocation timestamps.
- Package and assignment states will be finalized before Phase 7 to preserve current workflow compatibility.

## Transaction boundaries

- Login/session creation.
- Refresh-token rotation and reuse response.
- Invitation acceptance and membership/role creation.
- Approval decision and resulting employee/rider activation.
- Package creation with initial tracking event.
- Assignment replacement.
- Customer request approval into a package.
- Sensitive role or permission changes with audit entry.

## Legacy import policy

- No automatic localStorage import.
- A future admin-controlled importer validates schema, identities, relationships, tenancy, phone/email formats, statuses, and identifier collisions.
- Import runs in preview mode first and emits a signed audit report.
- Original IDs are retained only for approved valid records and stored as legacy references when they cannot be primary IDs.
